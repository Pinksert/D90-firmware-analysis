# Nikon D90 官方固件解析

尼康 **D90**（2008 年发布）官方固件的逆向解析。与 D300 一样，D90 的固件是**明文**；不同之处在于它的官方发布文件是一份**单文件**——前 524,290 字节是协处理器 A 段、紧接着 7,340,032 字节是主控 B 段，两段直接拼接、各自带 2 字节 CRC 收尾，整包与 D300 / D300S 解出的净体积**完全一致**（524,290 + 7,340,032），说明三台机器用的是同一套烧录布局。

> 姊妹项目：[D300 明文固件解析](https://github.com/Pinksert/D300-firmware-analysis) · [D300S 加密固件解析](https://github.com/Pinksert/D300S-firmware-analysis) · [D300 电磁光圈指令级比对](https://github.com/Pinksert/D300-electromagnetic-aperture-analysis)

## 处理器平台（解析结论）

- 架构：Fujitsu **FR 系列 32 位 RISC，大端**；RTOS = Softune REALOS/FR（micro-ITRON）。
- **A 固件（IO 协处理器）**：负责测光 / 对焦 / 按键等。
- **B 固件（主控 MCU）**：负责 UI + 图像处理 + 多语言文本。
- **加密状态**：明文未加密（与 D300 一致；D300S 则从这一代起改为三层 XOR 加密包）。
- 整机至少 3 颗处理器：EXPEED 图像 ASIC ＋ 主控 MCU(B) ＋ 协处理器 MCU(A)。

## 固件 bin 文件分析报告（D90）

分析对象：`D90Update/D90_0101.bin`（来自 F-D90-V101W.exe 类官方升级包） · 分析方式：静态二进制分析（熵扫描 / 字符串提取 / 校验和验证）

- **D90_0101.bin 大小**：7,864,322 B（= 0x780002 = A 0x80002 + B 0x700000）
- **固件版本**：A Ver. 1.00 / B Ver. 1.01a
- **CPU 架构**：Fujitsu FR
- **CRC-16 校验**：A / B 两段均通过
- **加密状态**：明文（未加密）

### 一、总体结论

这是 **Nikon D90 数码单反官方固件（单文件明文包）**。尼康把相机固件组织成两段顺序烧写的映像：

- **Firmware A（`D90_A.bin`，524,290 B）**——IO 协处理器的**程序代码**映像，内含 Fujitsu FR 机器码、RTOS 内核、引导与升级逻辑，以及一段 **NEC CIPHERUNICORN-S** 版权串（见 3.3；该库在机身内部的实际用途**未经验证**）。
- **Firmware B（`D90_B.bin`，7,340,032 B）**——主控 MCU 的**资源 / 数据 + 代码**映像，内含菜单 UI 的多语言文本表、图像处理参数表、ICC 色彩配置、PictBridge 打印脚本、GPS / Eye-Fi 相关字符串，以及一块高熵压缩资源（时区图、色轮、打印机画面）。

两段均未加密（整体熵 5.23，远低于 D300S 加密包的 8.00），尾部各带 2 字节 CRC-16 校验，且校验值**完全匹配**，说明文件完整未被篡改。

**最意外的一点**：A 段版本头写的是 `Ver 1.00`、构建于 **2008/09/12**；B 段版本串却写着 `Ver.1.01a … 2014/07/18`——**同一份文件里，两段固件的编译日期相差整整 6 年**。尼康官方下载中心只列出过一次 D90 机身固件更新（2014/08/26，A:1.00 / B:1.01），更新说明仅一句「加入对失真控制数据 Ver. L:2.000 及更新版本的支持」。也就是说：**2014 年那次更新只动了主控 B 这一半，协处理器 A 自 2008 年出厂起六年没有变过**。

### 二、校验和机制（已验证）

两段镜像的**最后 2 字节**是 CRC-16 校验值，算法为 **CRC-16/XMODEM**（多项式 `0x1021`，初值 `0x0000`，非反射，无输出异或），以**大端序**存放，覆盖范围为「整段长度 − 2」字节。

| 文件 | 文件长度 | 参与校验长度 | 存储值 | 计算值 | 结果 |
| --- | --- | --- | --- | --- | --- |
| `D90_A.bin` | `0x80002` | `0x80000` | `63 CC` | `63 CC` | ✔ 通过 |
| `D90_B.bin` | `0x700000` | `0x6FFFFE` | `C2 AB` | `C2 AB` | ✔ 通过 |

Python 验证：`binascii.crc_hqx(data[:-2], 0)`

### 三、D90_A.bin（Firmware A）解析

#### 3.1 文件头（0x00 – 0x3F，共 64 字节）

```
00000000  01 00 02 00 08 09 12 10  44 39 30 20 20 46 69 72  |........D90  Fir|
00000010  6d 77 61 72 65 20 41 20  43 6f 70 79 72 69 67 68  |mware A Copyrigh|
00000020  74 20 4e 69 6b 6f 6e 20  43 6f 72 70 2e 00 01 13  |t Nikon Corp....|
00000030  00 00 00 00 00 00 00 00  00 00 00 00 00 00 1b 00  |................|
```

| 偏移 | 长度 | 原始字节 | 含义 |
| --- | --- | --- | --- |
| `0x00` | 2 | `01 00` | 固件版本号，BCD 编码 → Ver. 1.00 |
| `0x02` | 2 | `02 00` | 保留 / 子版本字段 |
| `0x04` | 4 | `08 09 12 10` | 构建日期戳，BCD → 2008/09/12（末字节 `0x10` 为内部构建序号，类同 D300 的 `0x13`） |
| `0x08` | 37+1 | `"D90  Firmware A Copyright Nikon Corp." + 00` | 机型与版权标识串（注意型号字段是**定长双空格**对齐：「`D90  `」），0x2C 处 NUL 结束 |
| `0x2D` | 17 | `01 13 00 … 00` | 头部参数区（含义未明，多为 0） |
| `0x3E` | 2 | `1b 00` | 小端 16 位值 = `0x001B` (27)，疑为头部长度 / 条目数 |

> 机型串里「`D90  `」（双空格）是各机 A 头型号字段定长对齐的痕迹：D300 是「`D300 `」、D300S 是「`D300S`」、D90 是「`D90  `」，长度不一，回退读取时需按实际字节对齐。

#### 3.2 区域布局（64 KiB 分块熵值）

| 偏移范围 | 大小 | 熵 | 性质 |
| --- | --- | --- | --- |
| `0x00000 – 0x060000` | 384 KiB | 6.66 – 6.80 | FR 机器码主体（程序） |
| `0x060000 – 0x070000` | 64 KiB | 5.08 | 数据表（约 33% 为 0xFF、16% 为 0x00） |
| `0x070000 – 0x080000` | 64 KiB | 2.27 | 稀疏数据表 + 73% 0xFF 填充 |
| `0x080000 – 0x080002` | 2 B | — | CRC-16 = `0x63CC` |

符合「代码段 + 数据段 + 对齐填充」的典型嵌入式映像布局（Flash 擦除态为 0xFF）。

#### 3.3 关键内嵌字符串

| 偏移 | 内容 | 说明 |
| --- | --- | --- |
| `0x000008` | `D90  Firmware A Copyright Nikon Corp.` | 固件标识 |
| `0x06189C` | `CIPHERUNICORN-S COPYRIGHT (C) NEC CORPORATION 2006` | NEC CIPHERUNICORN-S（128 bit 分组密码）的库标识串。它**只能证明这个库被链进了 A 固件**（串两侧直接是代码/数据字节，无 NUL 结尾，周围也没有调用点、密钥表或名称指向它）。 |
| `0x07E4CE` | `Softune REALOS/FR is Realtime OS for FR Family, based on micro-ITRON COPYRIGHT(C) FUJITSU LIMITED 1994-1999` | REALOS/FR 实时操作系统（micro-ITRON 标准）——确认 CPU 为富士通 FR 系列 |

#### 3.4 关于 CIPHERUNICORN-S（结论同 D300 仓库）

要判断这串东西扮演什么角色，最直接的办法是看「有没有它」和「发布包是不是密文」是否跟着一起变。把同系列已经解出来的 A 固件全部扫了一遍：

| 机型 | 上市年份 | A 固件中是否有该串 | 发布包里的 .bin |
| --- | --- | --- | --- |
| D40（A 1.11） | 2006 | 有 | 明文 |
| D300（A 1.11） | 2007 | 有 | 明文 |
| D3（A 2.03） | 2007 | 无 | 明文 |
| **D90（A 1.00）** | **2008** | **有 @`0x6189C`** | **明文** |
| D300S（A 1.02） | 2009 | 有 | **加密** |
| D3S（A 1.03） | 2009 | 无 | **加密** |
| D700（A 1.04） | 2008 | 无 | 明文 |

两者完全不相关：带着这个串的三台（D40 / D300 / D90）发布包全是明文；而加密的那两台里，D3S **根本没有**这个串。所以：

- ❌ 它不是「尼康后期机型的固件加密体系」；
- ❌ A 固件里也不存在「用于解开新版加密包的解密例程」；
- ✅ 能确认的只有一条：**这台机器里链接了 NEC 的商用分组密码库**。

它大概率属于机身内部某项功能（存储卡认证、机身数据保护之类）的密码能力——但这同样属于推测，固件没有留下任何线索，本仓库不下结论。

### 四、D90_B.bin（Firmware B）解析

#### 4.1 头部特征

B 文件**没有** A 那样的 ASCII 明文头，0x00 处直接就是机器码：

```
00000000  9f 80 50 00 00 00 c0 11  15 01 87 10 9f 8f 00 00  |..P.............|
```

**重点**：B 段前 16 字节在三台机器（D90 / D300 / D300S）之间**逐字节完全相同**（`9f 80 50 00 00 00 c0 11 15 01 87 10 9f 8f 00 00`），说明它们共用同一套 FR 启动引导向量。

版本信息以**签名块**形式放在映像中部（偏移 `0x18AC48`）：

```
Ver.1.01a D90  2014/07/18 This version is not tested
```

注意两点：
1. 这里的措辞是 `This version is not tested`，**没有** D300 / D300S 版本串里的 `for mass production`——含义未明，留作疑点；
2. 在 D90 的 B 固件里**没有搜到** `D90FirmwareSignature` 字面量（D300 有 `D300FirmwareSignature`），签名块的命名可能随版本变化，不影响上述结论。

#### 4.2 区域布局（64 KiB 分块熵值）

| 偏移范围 | 大小 | 熵 | 性质 |
| --- | --- | --- | --- |
| `0x000000 – 0x01FFFF` | 128 KiB | 6.04 – 6.71 | 启动 / 初始化代码 |
| `0x020000 – 0x0BFFFF` | 640 KiB | ≈0（全 0xFF） | 地址空洞 / 分区对齐填充 |
| `0x0C0000 – 0x270000` | 1.1 MiB | 6.24 – 6.74 | 主代码段 + 图像处理参数表 |
| `0x180000 – 0x1BFFFF` | 256 KiB | 5.75 – 6.59 | 代码 + 数据表（含 30% 以上 0x00 区） |
| `0x280000 – 0x530000` | 1.8 MiB | 1.3 – 4.3 | 低熵数据表（大量 0x00，稀疏区占 70%+） |
| `0x540000 – 0x570000` | 192 KiB | 6.43 – 6.68 | 代码 / 参数 |
| `0x550000 – 0x580000` | 192 KiB | 7.78 – 7.81 | **高熵压缩 / 加密数据块**（近乎随机，为压缩资源：字库 / 图形 / 内置图片） |
| `0x580000 – 0x6FFFFF` | 1.5 MiB | ≈0（全 0xFF） | 尾部对齐填充 |
| `0x700000 – 0x700002` | 2 B | — | CRC-16 = `0xC2AB` |

#### 4.3 多语言 UI 文本表

文本区对应的是一份「语言选择菜单」的原生语言名列表。关键事实：

- D90 说明书（简体中文）第 **204** 页明确列出 **17 种**界面语言（比 D300 多**丹麦语 Dansk、挪威语 Norsk** 等；D300 = 15 种，D300S = 17 种）。
- 固件里**每个语言名出现 34 次 = 17 × 2**——存在两份并列的语言清单，所以「字符串出现次数」**不能直接当作语言种数**（跨代都踩过的坑）。

文本编码与 D300 同套尼康自定义压缩：常用 ASCII 字符占 1 字节；带重音的拉丁字母（ñ、ç、ê、ö、å 等）以及西里尔、CJK 字符使用双字节转义序列（如 `a4 00` = ñ、`9c 00` = ç），分隔标记各代不同：

| 机型 | 文本分隔标记 | 计数 |
| --- | --- | --- |
| D300 | `0F 07` | 4,948 |
| D300S | `0F 08` | 5,033 |
| **D90** | **`0F 09`** | **3,764** |

——`0F07 / 0F08 / 0F09` 是一代一个的资源编译器记号，可作为区分三代固件的小指纹。

#### 4.4 资源与功能性字符串（抽样，计数格式为 D90 : D300 : D300S）

| 类别 | 位置 / 词条 | 计数 | 说明 |
| --- | --- | --- | --- |
| 短片 / 视频 | `1280x720 (16:9)`、`640x424`、`320x216`、HDMI 输出 | 见 D300S 独有项 | D90 是「第一台视频单反」，但**没有**独立麦克风增益设置（`Microphone` 0:0:4） |
| Pictmotion | `Pictmotion` | **34:0:0** | **D90 独有**（机内幻灯片动画） |
| 失真控制 | `Distortion control` | **4:0:0** | **D90 独有**（对应 2014 失真控制数据更新） |
| 鱼眼 | `Fisheye` | **19:0:0** | **D90 独有** |
| 电池手柄 | `MB-D80` | **213:0:0** | 含 AA 电池型号 `LR6 / HR6 / FR6 / ZR6`（D300/D300S 为 MB-D10 / MB-D300 系） |
| 无线网卡 | `Eye-Fi` | 51:0:68 | D90 已支持 Eye-Fi 上载，但少于 D300S |
| 润饰 / 剪片 | `Edit movie` | 0:0:3 | 仅 D300S |
| 虚拟水平 | `Virtual horizon` | 0:0:6 | 仅 D300S |
| AF 微调 | `AF fine tune` | 0:5:9 | D300 / D300S 有，D90 没有 |
| 间隔定时 | `Interval timer` | 0:3:3 | D300 / D300S 有，D90 没有 |
| RAW 处理 | `NEF (RAW) processing` | **6:0:46** | ⚠️ **不是 D300S 独有**：是 **D300 没有、D90 / D300S 都有**（D90 说明书第 220 页有此功能） |

> 词条计数口径：**全篇不区分大小写**；固件侧统计的是「出现次数」，说明书侧统计的是「命中页数」，二者不可混用。

文件系统相关字符串（抽样）：`A:\DCIM\100ND90\`、`NCSETUP1.BIN`、`MSDOS5.0`、`HDISCVRY.DPS`（PictBridge / DPS）、`Softune REALOS/FR` @`0x750`（B 内也确认跑 REALOS/FR）。

### 五、与 D300 / D300S 横向对比

#### 5.1 体积与烧录布局

| 项目 | D90 (V1.00/1.01a) | D300 (V1.11) | D300S (V1.02) |
| --- | --- | --- | --- |
| A 段大小 | 524,290 | 524,290 | 524,290 |
| B 段大小 | 7,340,032 | 7,340,032 | 7,340,032 |
| 发布形态 | 明文单文件（A+B 直拼） | 明文分两个 bin | 加密包（解出后体积同上） |
| CRC | A `63CC` / B `C2AB` 通过 | 通过 | 解密后通过 |

#### 5.2 字节级相似度（未对齐、同偏移逐字节相等比例）

| 对比对 | B 段（主控） | A 段（协处理器） |
| --- | --- | --- |
| D90 ↔ D300 | **34.60%** | 8.18% |
| D90 ↔ D300S | 26.38% | 6.90% |
| D300 ↔ D300S | 26.97% | 13.55% |

- 主控 B 段上，**D90 比 D300S 更亲 D300**（34.60% > 26.97%），与发布顺序 2007→2008→2009 一致——官方口径里的「小改款」D300S，在字节层面反而不是最亲的。
- 协处理器 A 段三对都只有个位数到十几，其中 **D300 ↔ D300S 最高（13.55%）**——它俩是同一块板子，但整体也只共用约一成字节。

#### 5.3 内置图片资源（SHA-256 逐字节比对）

固件里藏着相机自己要用的 JPEG 资源：连接打印机时显示的画面、白平衡色轮、以及时区地图上配的城市照片。AI 用「SOS 感知」提取法从三台 B 固件各切出图片，再做哈希比对：

| 机型 | 提取张数 | 与 D90 的逐字节相同张数 |
| --- | --- | --- |
| D90 | 34（1 PictBridge + 1 色轮 + 32 时区图） | 34 / 34 |
| D300 | 34 | **34 / 34（完全相同）** |
| D300S | 35（时区图重绘为 33 张） | 仅头 2 张相同 |

→ **图片资源按「平台代际」共用，不按机型走**：D90 与 D300 的 34 张内置图逐字节全等，而 D300S 反而把时区图全部重绘了一遍。

#### 5.4 疑点（说明书也解释不了）

1. **单 SD 卡槽的 D90 固件里，躺着 `R Slot` / `L Slot`（右卡仓 / 左卡仓）的成套词条**，连法语、意大利语的翻译都配齐了；真正有双卡槽讲究的 D300 / D300S 里反而搜不到这组词。像是给双卡槽机型预留的通用代码提前躺在了 D90 里，或是从某个内部原型机继承下来——暂无证据，记作未解之谜。
2. **`This version is not tested`**：B 段版本串里这句话没有官方解释，三台机器里只有 D90 的版本串带它。

### 七、附：可复现的分析方法

```bash
# 1. 拆分为 A / B 并校验 CRC（两段均通过）
python split.py
#   D90_A.bin :   524290 B   CRC 计算=63CC  存储=63CC   OK
#   D90_B.bin :  7340032 B   CRC 计算=C2AB  存储=C2AB   OK

# 2. CRC-16/XMODEM 校验（A / B 各自）
import binascii
d = open('D90_A.bin','rb').read()
print(hex(binascii.crc_hqx(d[:-2], 0)), d[-2:].hex())   # 0x63cc  '63cc'

# 3. 分块香农熵 → 定位代码段 / 数据表 / 0xFF 填充区 / 压缩资源块
```
